> 文档修订：2026.08.10
>
> 适用代码：当前 4 主题、外层 `Msg`、共享载荷和关闭协商工作区

## 版本标识

| 标识 | 当前值 | 含义 |
| --- | --- | --- |
| `qframework::frameworkVersion()` | `0.1.0-baseline` | 编译进 `QFramework.dll` 的诊断字符串 |
| `QFRAMEWORK_PLUGIN_IID` | `org.qframework.Module/1.0` | Qt 插件发现使用的 IID，不是框架语义版本 |
| 本文档修订 | `2026.08.10` | 文档与当前代码同步的日期 |

框架目前不执行 SDK/ABI 版本协商。三个值都不能单独证明插件二进制兼容；更新 SDK、
QFramework DLL、Protobuf 生成头或编译配置后，应重新构建模块并重启主程序。
`qframework::protobufRuntimeVersion()` 返回协议 DLL 编译时使用的 Protobuf 版本字符串。

## 命名空间与公开头文件

公开类型位于 `qframework` 命名空间，头文件位于 `Source\QFrameworkSdk`。模块应只
依赖这些 SDK 头、`MessageTopics.h` 和当前 Protobuf 生成头，不要包含
`Source\QFramework` 下的内部实现头。

| 头文件 | 用途 |
| --- | --- |
| `ModuleEndpoint.h` | 生命周期、主题、发布、日志和关闭协商 |
| `MessagePayload.h` | 不可变共享载荷及构造辅助函数 |
| `InProcessUiModule.h` / `InProcessNonUiModule.h` | 主进程 DLL 基类 |
| `ProcessUiModule.h` / `ProcessNonUiModule.h` | 子进程 EXE 基类 |
| `ProcessRuntime.h` | 子进程唯一运行入口 |
| `QFrameworkPlugin.h` | Qt 插件 IID |
| `QFrameworkVersion.h` | 框架诊断版本字符串 |

## 四个基类

| 类型 | C++ 基类 | Qt 基类 | 载入方式 | 关闭协商 |
| --- | --- | --- | --- | --- |
| `InProcessUi` | `InProcessUiModule` | `QWidget` | `QPluginLoader` | 支持 `canClose()` |
| `InProcessNonUi` | `InProcessNonUiModule` | `QObject` | `QPluginLoader` | 不主动询问 |
| `ProcessUi` | `ProcessUiModule` | `QWidget` | `QProcess` + `ProcessRuntime` | 当前不支持主进程同步 veto |
| `ProcessNonUi` | `ProcessNonUiModule` | `QObject` | `QProcess` + `ProcessRuntime` | 不主动询问 |

## ModuleEndpoint

| 成员 | 返回值与语义 |
| --- | --- |
| `moduleId()` | 返回框架绑定的模块 ID；绑定前为空。 |
| `publishedTopics()` | 返回允许发布的主题，默认空列表；注册后不支持动态修改。 |
| `subscribedTopics()` | 返回订阅主题，默认空列表；注册后不支持动态修改。 |
| `onStart()` | 默认返回 `true`；回调期间已经允许发布。返回 `false` 或抛出异常会撤销发布权限。 |
| `onStop()` | 默认空实现；入口关闭和有界排空之后调用。 |
| `canClose(reason)` | 默认返回 `true`；主进程 UI 模块可拒绝用户隐藏 Dock 或退出应用。 |
| `onMessage(topic, senderModuleId, data)` | 异步消息回调；`data` 在回调期间只读有效。 |
| `publish(topic, data)` | 兼容发布入口；把 `QByteArray` 包装为一个共享载荷后发布。 |
| `publishShared(topic, payload)` | 发布已有 `MessagePayload`；同进程订阅队列共享同一载荷对象。 |
| `isStopRequested()` | 停止开始后返回 `true`，供长循环协作退出。 |
| `logDebug/Info/Warning/Error(text)` | 写入集中日志并自动带入模块 ID。 |

`bindHost()` 和 `setRunning()` 只供框架生命周期边界使用。业务代码不得保存或删除
`ModuleHost`，也不应直接调用这两个函数。

## MessagePayload 与发布语义

```cpp
using MessagePayload = QSharedPointer<const QByteArray>;

MessagePayload makeMessagePayload(const QByteArray& data);
MessagePayload makeMessagePayload(QByteArray&& data);
```

- 左值版本创建新的只读 `QByteArray` 对象；Qt 隐式共享避免立即深拷贝字节缓冲。
- 右值版本把已有字节缓冲转移给共享对象。
- 空智能指针 `MessagePayload()` 无效；合法零字节消息必须用非空 `QByteArray` 构造。
- `publish()` 已经统一进入 `publishShared()`，旧模块无需为了新传输路径全部改写。
- 同进程中央总线只向各订阅队列复制智能指针。跨进程仍必须在 inline 编码或
  `QSharedMemory` 边界复制实际字节，不能跨进程共享 C++ 指针。
- `onMessage()` 签名没有改变，模块不能把收到的 `const QByteArray&` 保存到回调之后。

发布返回值不是“所有消费者已经处理完成”：

- 主进程发布同步完成权限、大小和各订阅队列入队检查。任一订阅者拒绝会返回
  `false`，但其他订阅者已经接收的消息不回滚。
- 子进程发布返回值只表示本地 `PublishQueue` 已接收；父进程最终接受或拒绝由异步
  publish ACK、计数和限频日志记录。
- `Reliable` 满时拒绝新项；`Latest` 满时只替换同主题仍在等待的最旧项，不覆盖其他
  主题或已经在途等待 ACK 的项。

## 关闭协商

```cpp
enum class ModuleCloseReason
{
    Hide,
    ApplicationExit
};

virtual bool canClose(ModuleCloseReason reason);
```

- 回调在主进程 GUI 线程同步执行，可以显示 Qt 确认框，但不能无限等待后台任务。
- 用户取消菜单勾选或点击 Dock 关闭按钮时，已加载的 `InProcessUi` 收到 `Hide`。
  返回 `false` 后 Dock 保持可见，菜单勾选恢复。
- 主窗口关闭时按 INI 模块顺序询问已启用且已加载的 `InProcessUi`，原因是
  `ApplicationExit`；任一返回 `false`，本次退出取消。
- 布局恢复、窗口 ready 和运行状态变化不调用 `canClose()`。
- `ProcessUi` 没有同进程模块对象，当前仍直接隐藏；最终应用退出时走原有 stop 流程。
- 保存失败、用户取消或有界保存等待超时都应返回 `false`。

## 线程规则

- 主进程模块的 `onStart()`、`onStop()` 和 `canClose()` 在主进程 GUI 线程执行。
- 子进程模块的 `onStart()`、`onStop()` 在子进程 Qt 主线程执行。
- 每个模块有独立输入队列和消息线程，`onMessage()` 在该消息线程执行。
- `publish()`/`publishShared()` 可从模块自己的任意线程调用。
- 子进程业务线程只进入受 `QMutex` 保护的本地队列；Socket 查询、编码和 write 只在
  `ProcessRuntime` 所属 Qt 线程执行。
- UI 模块不得从 `onMessage()` 直接访问控件；应以 `Qt::QueuedConnection` 返回 UI
  线程。
- 框架不使用 `Qt::BlockingQueuedConnection`，也不以 `QThread::terminate()` 强杀回调。

## 生命周期顺序

1. 按 `[Modules]/Names` 顺序读取并载入启用模块。
2. 注册每个模块声明的发布与订阅主题。
3. 为当前模块开放发布入口，再调用 `onStart()`。
4. 全部目标首次到达 Running 或 Failed 后，中央总线才放开消息消费。
5. 停止时先关闭发布/接收入口，再在 `ShutdownDrainTimeoutMs` 内排空等待队列。
6. 安全时按反向顺序调用 `onStop()`、释放模块，最后刷新并停止日志。

框架不保存历史消息，也不在子进程重启后补发旧消息。跨进程统计区分
`dropped`、`rejected` 和 `abandoned`；停止、断开、故障和重启都会关闭入口、唤醒
等待并清理共享内存段。

主进程 DLL 回调超时后不能安全中断。框架保留仍运行的线程、endpoint 和 plugin
loader，不并发调用 `onStop()` 或卸载 DLL；子进程则以完整 `QProcess` 为隔离边界。

## 插件元数据

```cpp
#define QFRAMEWORK_PLUGIN_IID "org.qframework.Module/1.0"
```

主进程 DLL 类声明需要 `Q_OBJECT` 和：

```cpp
Q_PLUGIN_METADATA(IID QFRAMEWORK_PLUGIN_IID FILE "MyModule.json")
```

元数据至少包含 `ModuleId` 和 `ModuleType`，并与 INI 配置和实际 C++ 基类一致。DLL
更新后必须重启主程序。

## ProcessRuntime

```cpp
static int ProcessRuntime::run(QCoreApplication* application,
                               ModuleEndpoint* module);
```

它负责监督器参数、注册握手、主题声明、心跳、启动/停止、样式通知、双向有界队列、
inline/共享内存传输、ACK、Debug 限时等待和 UI 子进程窗口句柄。模块所有权转交给
运行时；业务代码不要直接建立模块间 Socket、共享内存或伪造框架参数。

## 当前主题宏

`MessageTopics.h` 当前只保留 4 个宏：

这 4 个宏只命名路由主题，不声明额外的内层消息。它们的负载都必须是序列化后的外层
`Msg`；具体业务字节由发布者写入 `Msg.str`，再由订阅者按双方约定解释。

| 宏 | 仓库内当前情况 | 示例 INI 策略 |
| --- | --- | --- |
| `QFRAMEWORK_IMAGE_RAW` | 配置和测试引用；没有生产模块实现 | `Latest`，容量 4，最大 16 MiB |
| `QFRAMEWORK_IMAGE_PROCESSED` | 只保留主题名；当前模块/测试没有实际发布 | 继承 `Reliable/256/16 MiB` |
| `QFRAMEWORK_LOG_DISPLAY` | 四个演示模块和测试引用 | 继承 `Reliable/256/16 MiB` |
| `QFRAMEWORK_STATUS` | 四个演示模块和测试引用 | 继承 `Reliable/256/16 MiB` |

框架并不限制模块只能使用这些宏。任意模块可在 `publishedTopics()` 和
`subscribedTopics()` 中声明其他稳定 `QString`，未配置的主题继承全局规则。
`MessageBus` 不验证主题对应哪个 Protobuf 类型。

## 当前 Protobuf 契约

`Source\QFrameworkProtocols\Protos\master_message.proto` 现在只定义一个枚举和一个
消息：

```proto
enum MsgType {
  None = 0;
  Test = 1;
}

message Msg {
  MsgType type = 1;
  int64 time = 2;
  string src = 3;
  string dst = 4;
  bytes str = 5;
}
```

字段语义：

| 字段 | 语义 |
| --- | --- |
| `type` | 当前只有 `None`、`Test` 两个兼容值，框架不读取它 |
| `time` | 发送时间，单位毫秒；业务方负责赋值和解释 |
| `src` | 来源模块名称；与框架额外传给 `onMessage()` 的 `senderModuleId` 不是同一校验机制 |
| `dst` | 业务目标名称；中央总线不会据此自动定向 |
| `str` | 不透明二进制业务载荷；不能经过 `QString`/UTF-8 文本转换 |

模块包含 `Generated/master_message.pb.h`，手工序列化 `Msg` 为 `QByteArray` 后发布；
接收方先解析 `Msg`，再按业务约定解释 `str`。框架不定义任何 SQL、ADB、设备、图像、
日志或状态内层消息，也不为 `str` 提供同步 RPC、关联 ID 或超时管理。

## 日志级别

`LogLevel` 包含 `Debug`、`Info`、`Warning`、`Error`。集中日志行包含毫秒时间、级别、
模块 ID、线程 ID 和文本。Qt 全局消息处理器也捕获 `qDebug`、`qWarning`、
`qCritical` 和 Fatal；无法判断来源时模块 ID 为 `Unknown`。
