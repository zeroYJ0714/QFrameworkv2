## 当前能力基线

| 范围 | 当前实现 |
| --- | --- |
| 模块 | `InProcessUi`、`InProcessNonUi`、`ProcessUi`、`ProcessNonUi` 四类模块；DLL 插件与 EXE 子进程统一使用 `ModuleEndpoint` |
| 消息 | 每订阅者、每主题有界队列；`Reliable` 满时拒绝，`Latest` 满时替换同主题最旧等待项；发布与订阅列表在启动时冻结 |
| 载荷 | `publish()` 兼容入口；`MessagePayload`/`publishShared()` 让同进程订阅队列共享不可变 `QByteArray` 对象 |
| IPC | 小消息走 `QLocalSocket`，达到阈值的大消息走 `QSharedMemory`；父到子 delivery ACK、子到父 publish ACK 回收在途槽位和共享段 |
| 协议 | `QFrameworkProtocols` 的当前业务协议只保留 `MsgType` 和外层 `Msg`；框架把 `Msg.str` 视为不透明字节，不定义 SQL、ADB 等内层消息 |
| 生命周期 | 异步启动、心跳、独立停止 deadline、自动/手动重启、有界排空；停止、断开、故障和重启都会关闭入口并清理等待资源 |
| UI | Qt 自绘无边框标题栏、Dock/标签页、布局预设、QSS 切换、子进程 HWND 嵌入和合并 resize |
| 关闭 | 已加载的 `InProcessUi` 可用 `canClose(Hide/ApplicationExit)` 拒绝用户隐藏或应用退出；`ProcessUi` 仍沿用直接隐藏行为 |
| 日志 | 集中异步日志，普通记录默认每 100 ms 批量刷新；显式刷新、Fatal、滚动和停止立即落盘 |

## 固定开发条件

| 项目 | 要求 |
| --- | --- |
| Qt | 5.15.2，Win32 使用 `msvc2019`，x64 使用 `msvc2019_64` |
| Visual Studio | VS2017、VS2026 |
| 编译工具集 | `v141` |
| C++ | C++17 |
| Protobuf | 3.21.12 |
| 运行库 | Debug `/MDd`，Release `/MD` |
| 工程系统 | 唯一 `QFramework.sln`，只维护 `.sln` 和 `.vcxproj` |

`config\QFramework.ini` 是只读运行配置。程序不会写回它；相对路径均以该 INI
所在的 `config` 目录为基准。布局文件和日志目录可以由运行时写入，但不代表 INI
本身会被修改。

## 示例与协议位置

四种模块类型均有可构建示例：

- `Modules\InProcessUiExample`
- `Modules\InProcessNonUiExample`
- `Modules\ProcessUiExample`
- `Modules\ProcessNonUiExample`

协议与 SDK 的当前入口：

- `Source\QFrameworkSdk\ModuleEndpoint.h`：模块生命周期与发布接口；
- `Source\QFrameworkSdk\MessagePayload.h`：不可变共享载荷；
- `Source\QFrameworkProtocols\MessageTopics.h`：当前保留的 4 个主题宏；
- `Source\QFrameworkProtocols\Protos\master_message.proto`：`MsgType` 和外层 `Msg` 的协议源；
- `config\QFramework.ini`：运行时默认值和当前示例主题覆盖。

新模块应从 Visual Studio 的 Qt 默认项目开始配置，不要把示例目录当成仓库自定义
项目模板。新增或修改外层协议时，只修改 `master_message.proto` 并让
`QFrameworkProtocols.vcxproj` 调用仓库内的 Protobuf 3.21.12 重新生成代码。本轮生成
已经完成；示例/测试中的旧拆分消息引用仍不是 `Msg` 新协议的一部分。

## 当前主窗口说明

主窗口使用 Qt 自绘无边框标题栏：左侧为“布局、模块、样式”菜单，右侧为最小化、
最大化/还原和关闭按钮。Dock 分隔条保留约 5 px 鼠标命中范围、中央 1 px 绘制。
已加载的主进程 UI 模块现在可以在用户隐藏 Dock 或退出应用前进行关闭确认；取消后
Dock、菜单勾选和主窗口保持原状态。

自动测试可以验证菜单状态、布局恢复、IPC 和生命周期，但真实桌面上的鼠标拖放、
多显示器/DPI、系统菜单、视觉裁切以及模块实际保存草稿仍需人工验收。
